🔄 Flujos paso a paso

Qué ocurre exactamente desde que el usuario habla hasta que obtiene respuesta.

🤖 Modo IA — Alt+Super+G
1
Ctrl+Space (pulsación 1)

talk2ai-keys lee /dev/input y llama a Handy.

handy --toggle-transcription
2
Handy graba audio

PipeWire → WAV en local. Pitido de inicio.

3
Ctrl+Space (pulsación 2)

Handy para la grabación y transcribe (Whisper local ~1.2s).

4
Handy guarda en SQLite + llama al handler

El handler lee el modo = "ai" y sale inmediatamente (<10ms).

5
talk2ai-daemon detecta nueva fila

Polling SQLite cada 1s. Escribe "processing" en ai-state → tray anima el icono.

6
Driver IA — streaming

Llama al script del driver activo con el texto. El CLI devuelve la respuesta en streaming por stdout.

~/.talk2ai/ia/<driver> "$prompt"
7
espeak-ng — TTS en streaming

Cada frase completa se habla al instante. Sin esperar a la respuesta entera.

8
Si hay enlaces — notificación KDE

URLs marcadas con [ENLACE: url] generan una notificación con botón "Abrir" → xdg-open. También aparecen en la ventana debug.

⌨️ Modo Dictado — Alt+Super+H
1
Ctrl+Space (pulsación 1)

talk2ai-keys detecta la tecla y activa la grabación en Handy.

handy --toggle-transcription
2
Habla con normalidad

Handy graba. El foco sigue en tu ventana — puedes seguir usando el ratón.

3
Ctrl+Space (pulsación 2)

Handy para y transcribe (Whisper local ~1.2s).

4
Handy llama a talk2ai-handler

El handler lee mode = "dictate" y lanza un subshell completamente desacoplado.

disown + </dev/null
5
Handler sale — Handy libre (<10ms)

Handy no espera. No crashea. El subshell vive de forma independiente.

6
0.5s después — ydotool type

Tiempo suficiente para que Handy libere el foco. ydotool inyecta el texto via /dev/uinput directamente en el kernel — sin portal KDE.

7
Texto aparece en la ventana activa

Editor, navegador, terminal — donde estuviera el cursor.

📁 Estado compartido ~/.talk2ai/

Archivos de texto plano que coordinan todos los componentes. Sin base de datos, sin sockets propios.

📄 mode

Modo activo del sistema.

✎ Escribe: talk2ai-keys, tray ▶ Lee: daemon, handler, tray Valores: ai · dictate

📄 driver

Driver IA activo.

✎ Escribe: tray ▶ Lee: daemon, tray Valores: gemini · claude · ollama · …

📄 ai-state

Estado de procesamiento IA. Controla la animación de latido del tray.

✎ Escribe: daemon ▶ Lee: tray (QFileSystemWatcher) Valores: idle · processing

📄 model

Nombre del modelo activo. Aparece en el tooltip del tray.

✎ Escribe: daemon (al arrancar) ▶ Lee: tray Ej: gemini-2.5-flash-lite, gpt-4o, claude-opus…

📄 debug

Flag de activación de la ventana debug. Su existencia activa el modo debug.

✎ Escribe: tray (touch / unlink) ▶ Lee: daemon, handler Existe = debug ON · No existe = debug OFF

📄 debug.log

Log de sesión Q&A. Formato: timestamp|tipo|texto

✎ Escribe: daemon (Q/A/STAT/L), handler (D) ▶ Lee: tray (ventana debug) Tipos: Q · A · D · L · STAT · INFO · SEP

📄 voice-prompt.md

Instrucciones TTS enviadas al modelo. Controla estilo de respuesta y manejo de URLs.

✎ Escribe: usuario / instalador ▶ Lee: driver (TALK2AI_VOICE_PROMPT)

📂 ia/<driver>

Script ejecutable del driver activo. Recibe el prompt y devuelve la respuesta en streaming.

✎ Instala: daemon (desde repo) ▶ Ejecuta: daemon Contrato: stdin=$1 · stdout=stream · env=TALK2AI_*

📂 context/<driver>.md

Personalidad y contexto persistente del driver activo.

✎ Escribe: usuario ▶ Lee: driver (TALK2AI_CONTEXT_FILE)
🤖 Contrato del driver cómo añadir un nuevo backend IA

Cualquier script ejecutable en ~/.talk2ai/ia/ puede ser un driver. El daemon es agnóstico al modelo y al proveedor.

~/.talk2ai/ia/mi-driver
#!/bin/bash  # o Python, Node, cualquier ejecutable

Entrada
  $1                      → texto del usuario

Entorno (exportado por el daemon)
  TALK2AI_MODEL          → modelo a usar  (ej: gemini-2.5-flash-lite, gpt-4o, claude-opus…)
  TALK2AI_VOICE_PROMPT   → ruta a instrucciones TTS
  TALK2AI_CONTEXT_FILE   → ruta a contexto de personalidad  (puede estar vacío)

Salida
  stdout                 → texto plano en streaming, sin markdown
                            URLs en formato: [ENLACE: https://...]
  stderr                 → mensaje de error si algo falla

Exit code
  0                      → éxito
  ≠ 0                    → error  →  daemon habla mensaje aleatorio + guarda en errors.log
📦 Dependencias del sistema

Todas instalables desde los repos de Arch / CachyOS.

Herramienta Función Usado en
handy Speech-to-Text local con Whisper. Graba, transcribe y guarda en SQLite. ambos
AI CLI driver CLI del driver IA activo (Gemini, Claude, Codex, ollama…). Cualquier ejecutable en ~/.talk2ai/ia/ puede ser driver. IA
espeak-ng Síntesis de voz (TTS) en español. Soporta SSML para pronunciar nombres propios. IA
ydotool + ydotoold Inyección de teclado via /dev/uinput. Funciona en Wayland sin portal KDE. Dictado
python-evdev Lectura directa de /dev/input para atajos globales (talk2ai-keys). Requiere grupo input. ambos
python-pyqt6 Tray icon, ventana debug Q&A y QFileSystemWatcher para actualizaciones en tiempo real. UI
notify-send Notificaciones KDE con botón "Abrir" para los enlaces de las respuestas IA. IA
xdg-open Abre URLs en el navegador por defecto al pulsar "Abrir" en la notificación. IA
sqlite3 Lectura directa de la BD de Handy para el polling del daemon. IA
xdotool Fallback para X11 cuando ydotool no está disponible. Dictado
